Debian and RHEL packages, Docker images (`ghcr.io/llmsyscore/llm-systems-manager:v3.1.0`) and the Homebrew tap (`brew install llmsyscore/tap/llm-systems-manager`) follow the same tag. After upgrading, restart the manager, then the alarm engine, then push the new agent to every host from **Admin › Agents › Update all**.

This release has no new headline feature. It is the bug-fix, performance and security-hardening pass that followed v3.0.0: 41 pull requests closing more than 60 issues from the pre-release audits, load tests and fresh-machine installs.

---

## Spotlight

### Security hardening

- **No built-in admin password.** The installer creates a temporary password for the first sign-in, which then sets a new one. The old shipped password no longer signs in; `admin_password.py reset` makes a temporary one at any time.
- **Controlled agent enrollment.** New agents need the enrollment secret and the manager's certificate fingerprint (both under **Admin › Agents › Manage ▾ › Enrollment**, with a ready-made install command), talk HTTPS from the first request, and are accepted only while enrollment is open: a 15-minute window after each manager start, or **Open / Extend / Close** by hand. Registration is size-limited, rate-limited per address and capped while waiting for approval.
- **Certificates carry a role.** Every certificate names the manager, the alarm engine or one agent, each side requires the role it expects, and agents stay on HTTPS once they have checked it.
- **A budget for the routes that need no login.** Past 600 requests a minute the manager answers 429; signed-in users and approved agents are not counted. System Health and the audit log show the floods.
- **Smaller changes.** Per-agent stream keys; mail server certificates verified; alert channel secrets masked and channel changes admin-only; a tighter policy for the pages served through the manager; Terminal, service settings and Auto-Tune Apply admin-only; the Agent security switch relaxes reads only; Docker generates the alarm engine tokens and refuses two equal ones.

### Faster under load

- **Manager.** A 1024-deep listening queue, no cap on idle browser connections, the user file parsed once, and content-stamped static files cached for a year: a returning browser loads the dashboard with 1 request instead of 75.
- **Alarm engine.** History reads run on a 4-worker pool off the event loop and fetch at a grain that fits the chart: a 24-hour read across 8 hosts drops from 86 ms to 10 ms.
- **InfluxDB.** A 0 s WAL fsync delay (write latency 106 ms to 5 ms) and 16 MiB cache snapshots (reads of recent data stay fast all day); the tuning refresh now reaches every install path.
- **Overall tab** paints in under a second instead of about ten. **Agent** InfluxDB probes read one series instead of all of them.

### Easier to see what the system is doing

- **System Health** shows status pills per service, reports the alarm engine as degraded while InfluxDB is down, and, when nothing is wrong, offers **Recent** operations, **Capacity** bars and **Trends** sparklines in the right-hand column.
- **Admin › Agents** shows one shared "update running" state and a visible "update to" line per agent; the "restart pending" badge clears by itself.
- **Install, crash and daily diagnostic reports**, anonymous and asked about once at install, with the last report viewable under **Settings › Telemetry & analytics**. The README lists every field.

## Upgrade notes

- **Restart both services and update the agents.** The manager, alarm engine and agent versions all changed. Order: manager, then alarm engine (split install: copy `ae-tls.*` across first), then **Admin › Agents › Update all**. Agents older than `v2026.08.16-1` need an update before they can be newly approved; agents older than `v2026.09.04-1` need a restart after approval.
- **Admin password.** If an admin account still has the password older releases shipped, it stops working after this update. Run the updater and answer yes to get a temporary password, or run `admin_password.py reset` on the manager host. Accounts with their own password are not affected. Packages and Docker: create the first admin password with `admin_password.py reset` after installing.
- **Enrollment.** Upgraded managers start with no enrollment secret: generate one from **Admin › Agents › Manage ▾ › Enrollment** when you are ready to add machines. Approved agents keep working. Enrollment is open for 15 minutes after each manager start (`[manager.agents].enrollment_mode` = `auto`); set `open` or `closed` to change that.
- **Stream keys.** After the manager restarts on this version, agent log, download and build streams can fail for up to one heartbeat until each agent receives its new key. The previous key file stays on disk unused.
- **InfluxDB tuning.** Run `install.sh --update` (or `tools/installer/tune-influxdb.sh`) to apply the fsync and cache-snapshot changes on an existing install; it queues an InfluxDB restart. Package upgrades run it on their own.
- **New settings**, all in both example files and the Settings catalog: `[manager].listen_backlog`, `[manager.security].anon_request_budget_per_min`, `[manager.agents].enrollment_mode` and `enrollment_window_min`, `[alarm_engine.caches].max_hosts_per_metric`, `[notifications.smtp].ca_file`, and the `[manager.telemetry]` section. The default policy for proxied pages changed; a custom `proxy_html_csp` value is left untouched.
- **Alarm engine allowed origins.** The updater, package upgrades, Docker and Homebrew add the `https://` entries to `[alarm_engine].cors_origins`; on a split install the alarm engine host's own address replaces the manager's. Set `LLMSYS_PRIMARY_IP` when browsers reach the host on a different interface.
- **Homebrew upgrades** now add new config keys to an existing `llm-systems.toml` and leave the previous file next to it as `llm-systems.toml.bak.<timestamp>`.
- **Docker.** Two equal alarm engine tokens in `.env` stop the containers; change the management token before the next `compose up`. Tick **manager host** on the docker host's agent so its certificate includes the host address.
- **Reports.** The updater asks once about install and crash reports when run from a terminal; unattended updates and package or Homebrew upgrades keep them on and print the off switch.
- **Agents stay on HTTPS.** After turning HTTPS off for the manager or the alarm engine, delete `data/tls-roles.json` on each agent and restart it.
