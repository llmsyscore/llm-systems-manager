Debian and RHEL packages, Docker images (`ghcr.io/llmsyscore/llm-systems-manager:v3.4.0`) and the Homebrew tap (`brew install llmsyscore/tap/llm-systems-manager`) follow the same tag. After upgrading, restart the manager and update your agents. The alarm engine did not change.

This release works with a llama-server you installed yourself, lets you list, switch and benchmark the llama.cpp builds on each host, shows AMD GPU system memory and lets you pick which GPU an agent watches, and keeps Update all running after you leave the page.

---

## Spotlight

### Use the llama-server you already have

The agent now works with a `llama-server` it did not install: a distro package (apt or dnf), Homebrew, a release download or your own systemd service. It finds the running server, reads its port, models folder and settings, and starts, stops and restarts it from the dashboard. A server that starts after the agent is picked up on its own. A single-model service can be switched to multi-model mode from LLM Control, and the change is undone if the server does not come back. See [Using a llama-server you installed yourself](https://github.com/llmsyscore/llm-systems-manager/blob/v3.4.0/docs/DEPLOYMENT.md#using-a-llama-server-you-installed-yourself).

### llama.cpp builds: list, switch, compare

- **Installed builds.** **LLM Control → ⋯ → Installed builds** lists every llama.cpp build on the host: folder, backend (Vulkan, ROCm, CUDA, Metal, CPU), version, whether it runs, and which one is active.
- **Activate.** An admin can switch the server to another build. The dashboard checks the build first, restarts the server on it and waits for it to answer. If it does not start, the previous build comes back and the panel shows why.
- **Benchmark each build.** Offline and Live benchmark, Autotune, Quality guard and Report Card show a **Builds** row when more than one build is installed. Pick several to run the same settings on each, and every result is labelled with its build. Live benchmark and Report Card switch back to the starting build when the run ends, fails or is cancelled, and also after the agent or manager restarts in the middle of a run.

### GPU memory and GPU choice

- **GTT on AMD.** The GPU card shows how much system memory the GPU is using (GTT) under VRAM, with a chart of both over time.
- **Pick the GPU.** On a host with more than one GPU, **Admin → Agents** has a **GPU** dropdown. Automatic watches the card with the most memory, so a discrete card wins over an integrated one.

### Update all keeps going

**Update all** now runs on the manager. Closing the output window, switching tabs or leaving the page no longer stops it. Reopen the output from **Manage ▾ → Show Update all output**, or follow it on the Jobs tab.

### Smaller improvements

- **New addresses.** The install command is `bash <(curl -fsSL https://get.llmsysmanager.com/install.sh)` and the demo is at https://demo.llmsysmanager.com.
- **Reports.** New installs send a small daily check-in (install ID, version, operating system, install channel) when you agree to install reports. The detailed daily report stays off unless you turn it on. Existing installs keep their choices. `DO_NOT_TRACK=1` turns every report off.
- **Troubleshooting guide.** Common problems and their fixes now have their own page: `docs/TROUBLESHOOTING.md`.

## Upgrade notes

- **Restart the manager.** The alarm engine did not change and needs no restart.
- **Update your agents** with **Update all**. The agent changed, and the build tools and GPU dropdown need it.
- **Root helper.** If an agent's llama card shows a one-time command to update its root helper, run it once on that host.
- No config changes are needed.
