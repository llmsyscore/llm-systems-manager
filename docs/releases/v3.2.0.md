Debian and RHEL packages, Docker images (`ghcr.io/llmsyscore/llm-systems-manager:v3.2.0`) and the Homebrew tap (`brew install llmsyscore/tap/llm-systems-manager`) follow the same tag. After upgrading, restart the manager, then the alarm engine. The agent is the same as in v3.1.0.

This release adds installs on Rocky Linux, AlmaLinux and RHEL 10, a shorter config file, 23 more settings on the Settings tab, and moves the Tools tab pages to their own ports.

---

## Spotlight

### Install on RHEL-family 10

The script installer now sets up the manager, the alarm engine and InfluxDB on Rocky Linux, AlmaLinux and RHEL 10, using `dnf` for the system packages. Before, only the agent installed there. Hosts on version 9 of these systems use the `.rpm` package.

### A shorter config file

- **New installs** write a config file with only passwords, tokens, addresses and the choices made during the install. Every other setting uses its built-in default, so a later release that improves a default reaches your install too.
- **Every setting** is listed with its description in `config/llm-systems.toml.reference`.
- **Trim an older file.** `toml_reconcile.py slim` prints a copy of your config that keeps only the settings you changed. See "Trim your config file" in DEPLOYMENT.md.
- **23 more settings on Admin › Settings**, with plain labels and help, including a new **Timeouts & limits** group. Changes to how long an agent can go quiet before it shows as stale apply without a restart.

### Tools tab pages on their own ports

OpenClaw, LLM Chat and Image Generation now load from ports 5447 (HTTP) and 5448 (HTTPS) instead of the dashboard address, so a script in one of those pages cannot use your dashboard sign-in. The Tools tab signs you in to them on its own and shows a clear message when a port cannot be reached or its certificate has not been accepted yet.

### Smaller improvements

- **Faster dashboard reloads.** The dashboard page is served from a ready-made copy: about 9 ms instead of 158 ms, and many more page loads per second.
- **Next steps after an update.** `update.sh` ends with a numbered list for the host it ran on: restarts you put off, a temporary admin password when one was set, the alarm engine certificate copy on a multi-host install, where to refresh the InfluxDB tuning, which other hosts still need the update, and **Update all** for the agents.
- **System Health stream warning** shows only while the live-update connections are full or were refused in the last 10 minutes, and goes away by itself.

## Upgrade notes

- **Restart the manager, then the alarm engine.** Both versions changed. The agent did not change, so **Update all** is not needed.
- **Open ports 5447 and 5448.** Browsers that use the Tools tab need to reach the manager host on these ports. With the internal certificate, each browser accepts it once for port 5448: open `https://<manager-host>:5448/tools-ping` and accept it. Behind a reverse proxy, open the ports or forward them (DEPLOYMENT.md, "Protecting the Manager from Request Floods"). To keep the tool pages on the dashboard port, set `[manager].tools_port` and `tools_tls_port` to `0`.
- **OpenClaw.** Add `http://<manager-host>:5447` and `https://<manager-host>:5448` to `gateway.controlUi.allowedOrigins` on the OpenClaw host and reload it. Until then the OpenClaw page shows "Browser origin not allowed".
- **Docker.** The shipped compose file publishes 5447 and 5448. A compose file of your own needs those two ports added.
- **Config files.** Your existing config file is kept as it is. Upgrades now add only the keys the short install file contains, so new settings run on their defaults until you set them.
- **History left in the old `metrics.db`.** On some upgraded installs, benchmark results, tool runs, report cards, audit entries and hourly energy rows from before the database split stayed in the old `metrics.db`. The first start of this version copies them into the current database files and renames the old file `metrics.db.merged-<date>-<time>`.
- **Live-update threads** on Admin › Settings › Network must now be lower than **Worker threads**; a save that breaks this is refused with a message naming both.
