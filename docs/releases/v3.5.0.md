Debian and RHEL packages, Docker images (`ghcr.io/llmsyscore/llm-systems-manager:v3.5.0`) and the Homebrew tap (`brew install llmsyscore/tap/llm-systems-manager`) follow the same tag. After upgrading, restart the manager and the alarm engine, and update your agents.

This release redesigns the dashboard: a sidebar instead of the top bar, Dark and Light themes, and pages that share one look: tiles, charts and tables in sections you can fold, hide or pin. It also works with an LM Studio server you run yourself.

Try it without installing anything: [demo.llmsysmanager.com](https://demo.llmsysmanager.com).

---

## Spotlight

### A new dashboard

- **Sidebar and toolbar.** Pages sit in a sidebar grouped as Monitor, Operate and System. The toolbar on each page shows the state of every LLM server and holds the page's own controls, such as the provider filter and the 6, 12 or 24 hour range. Unpin the sidebar to give the page more room.
- **Dark and Light.** Two themes replace the nine earlier ones. Switch them at the bottom of the sidebar, or let the settings drawer follow your system. A saved earlier theme opens as Dark or Light. The Events and metrics page uses the same colours.
- **Overall.** At a glance tiles, token throughput as bars over the last 6, 12 or 24 hours, each LLM server, power and energy, and a watch list for forecasts, Tower, alerts and hosts.
- **All hosts and host pages.** All hosts shows every host's CPU, memory and disk in one table, with charts that compare hosts over time. Click a host to open its page: a host without an LLM server now has a page of its own.
- **llama.cpp, LM Studio and vLLM pages** show the server, tokens per hour, GPU, system and power for the host you pick.
- **Energy, Forecast and Manager** open with summary tiles, then charts and tables below: cost and savings, open findings and the next run, and the manager's own services, databases and response times.
- **Arrange your pages.** Fold a section with its arrow, hide sections from the settings drawer, and pin cards from any page to Overall.

### Use the LM Studio server you already have

The agent now finds an LM Studio server it did not set up: its port, the user running it and the `lms` command. A server started later is picked up within five minutes. The LM Studio card shows what it found and offers to save it, and explains what to do when the server is stopped, runs as another user or `lms` is missing. See [Using an LM Studio server you run yourself](https://github.com/llmsyscore/llm-systems-manager/blob/v3.5.0/docs/DEPLOYMENT.md#using-an-lm-studio-server-you-run-yourself).

### Smaller improvements

- **Model names.** Rename a model from the ⋯ menu in every view. Only the newest Tower download is named "Tower Model · <model>".
- **LM Studio log.** The server log reads the newest log file and keeps long replies short.
- **Faster pages.** Charts on hidden pages wait until you open them, and Overall no longer jumps while it loads.
- **Tower off.** With Tower turned off, pages no longer get an error when they load Tower insights.

## Upgrade notes

- **Restart the manager and the alarm engine.** Both changed.
- **Update your agents** with **Update all**. The agent changed for LM Studio detection.
- **Themes.** A saved theme other than Dark or Light opens as Dark (Frost opens as Light).
- **LM Studio port.** The agent's default LM Studio address is now port 1234, LM Studio's own default; the agent still finds a server on 1235. If LM Studio runs as another user on a port of your own, set `LMS_API_URL` in the agent config.
- No other config changes are needed.
